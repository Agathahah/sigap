# n8n workflows

Two workflows, exported as JSON so they are reviewed and versioned like code (no credentials, no phone numbers):

| File | What it does |
|---|---|
| `workflows/SigapAlertRouter.json` | every 15 minutes: `GET /v1/ops/alerts` → one message per open alert → `POST /v1/ops/alerts/{key}/ack` (only after the channel accepted it) |
| `workflows/SigapReviewCases.json` | weekdays 08:30: the five highest-priority assigned cases in one message with a link to the decision form; the form posts to `POST /v1/ops/cases/{id}/decision` |

Both workflows send through the channel set by `SIGAP_ALERT_CHANNEL` in `.env`: `email` (default, Gmail SMTP) or
`whatsapp` (Cloud API). WhatsApp needs a business number in the analyst's country: the Meta test number is a US
number and messages from it to +62 fail with error 130497 (ADR 0007).

n8n talks to SIGAP only through the ops API (ADR 0007). It never connects to Postgres.

## Run locally
1. `.env`: `SIGAP_OPS_API_KEY` (generated by `make env-secrets`), `SIGAP_API_URL_FOR_N8N=http://host.docker.internal:8000`,
   `SIGAP_ANALYST_WHATSAPP` (the analyst's number, digits only, e.g. country code 62 without "+"),
   `SIGAP_WA_PHONE_NUMBER_ID` (from the WhatsApp API Setup page), `N8N_ENCRYPTION_KEY`,
   `SIGAP_ALERT_CHANNEL` (`email` or `whatsapp`) and `SIGAP_ANALYST_EMAIL` (the Gmail address that sends and
   receives the e-mail channel).
2. Start the scoring API with the ops routes: `make docker-build && make docker-run` (or `make serve`).
3. `make n8n-up`, open http://localhost:5678 and create the local owner account.
4. `make n8n-import` loads both workflows.
5. Credentials (Settings → Credentials, or from a node):
   - **Header Auth** named `SIGAP ops key`: name `X-API-Key`, value = `SIGAP_OPS_API_KEY`. Select it in every
     HTTP Request node.
   - **WhatsApp API**: a system-user access token (Business Settings → System users) and the WhatsApp Business
     Account ID. Select it in both WhatsApp nodes.
   - **SMTP** named `SIGAP Gmail SMTP`: user = the Gmail address, password = a Gmail app password
     (Google Account → Security → 2-Step Verification → App passwords), host `smtp.gmail.com`, port 465, SSL on.
     Select it in both e-mail nodes.
6. WhatsApp Cloud API test number: add the analyst's number as a recipient on the API Setup page, then send any
   message from that phone to the test number. Free-form text is only delivered inside the 24-hour window that
   message opens.
7. Open a workflow and click **Execute workflow**. The decision form's test URL is shown on the *Decision form*
   node; after **Publish**, the production URL is `<WEBHOOK_URL>form/sigap-decision`.
8. After changing a workflow: `make n8n-export` (overwrites the files here), then `make check P=8b`.
9. After changing `.env`: `docker compose --profile ops up -d --force-recreate n8n` (workflows and credentials stay
   in the `n8n_data` volume).

Without Meta access, `make ops-demo` serves the same API with made-up cases on port 8001
(`SIGAP_API_URL_FOR_N8N=http://host.docker.internal:8001`) to build and test the HTTP side of the workflows.
